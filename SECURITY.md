# Security policy

## Supported versions

Security fixes go into the latest version on the App Store. Older versions, TestFlight builds and source builds from older commits are not supported.

## Reporting a vulnerability

Report privately. Don't open a public issue.

- On GitHub: the repository's **Security** tab, then **Report a vulnerability**.
- By email: [support@foliodesign.app](mailto:support@foliodesign.app), with "Security" in the subject.

Include the Folio version, iPad model and iPadOS version, what an attacker could do, and the smallest safe way to reproduce it. Remove cookies, tokens, credentials, private file links, account emails and device identifiers from your evidence.

In scope: Folio itself, for example credential exposure, unsafe navigation, access from page scripts to native code, file and download handling, and diagnostics that leak private data.

Out of scope: Figma's service, Apple's platforms and other users' accounts. This policy does not authorize testing them; report those to the vendor.

## What happens next

We review every report, ask only for what we need, fix confirmed issues and agree on disclosure timing with you. There is no bug bounty and no guaranteed response time. We credit reporters only with their consent.
